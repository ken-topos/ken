## Objective — ✅ **operator-COMMITTED scope**

Spawn/exec/wait with explicit argv and environment bytes; pipe and
descriptor-map construction; close-on-exec and **deny-by-default inheritance**;
`pidfd` identity and signalling where available; typed child-exit and signal
observation.

## ⛔ DECLARATIVE SPAWN PLAN — a raw post-`fork` callback is NOT acceptable

**Reason, and it is a real one:** a post-`fork` callback exposes a **restricted
process state in which the runtime's invariants are unstateable.** There is no
honest way to describe what Ken code may do there, so the surface must not offer
it.

⭐ **The plan must be extensible** to later attach namespaces, credentials,
cgroups, and sandbox policy **before the Ken runtime starts.** Design the plan as
an open structure now or every one of those becomes a breaking change.
